# DS4 optimization — Strix Halo / V4.1 Flash

Improve measured prefill/decode on `gfx1151`. Preserve numerical correctness, SSD
streaming, tool calling and the other backends (CUDA, Metal). One measured bottleneck
at a time. Keep `balanced` power settings. Preserve unrelated dirty files; never
restore whole files containing other work; never delete models or caches.

## Where state lives

- `ledger/CURRENT.md` (generated by `ak ledger truth`) is the current state: changes and
  their stage, live claims, suspect and rejected lines. Start there, then continue the
  latest handoff's next pending action. Don't redo established checks.
- `ledger/claims.jsonl` is the record. Add claims and stage changes with `ak ledger`;
  never edit it by hand.
- `findings/*.md`, NOTE.md, RESULTS.md and EXPERIMENTS.md are history. Search a section
  only to resolve a specific missing fact. STATE.md is retired.

## Never compute it in your head: use `ak`

`tools/agentkit/ak` (README in `tools/agentkit/`) prints one JSON object. Exit code 3 means
it refused: read `error` and `fix`, and follow the fix rather than working around it.

| Need | Command |
|---|---|
| A shape, dtype or byte count | `ak facts tensors MODEL --group --match NAME`; `ak facts decode-bytes MODEL --ceiling 223GB/s` |
| A bandwidth or rate | `ak rate --bytes … --time … --ceiling 223GB/s --calls N --expect-calls 'tokens*layers'` |
| Where the time goes | `ak budget budget.json` |
| Which gates a change needs | `ak gate required HEAD~1..HEAD` |
| Logit equality | `ak gate logits A_DIR B_DIR --save gate.json` |
| A/B benchmark | `ak ab build`, then `ak ab plan spec.json --out bench-ak-NAME.sh`, then `run_benchmark` |
| Recording a result | `ak ledger add / advance / set` |

Rules learned the hard way in this tree:
- **Write the unit on every number.** MB vs MiB, µs vs ms, per layer vs per token. Never type a model dimension: V4.1 Flash is not V4 Pro.
- **A counter only measures its own population.** Before quoting a rate, its call count must equal tokens × layers for the scope you mean. Prefill rows in a decode counter, or 6 experts counted as 8, made five instruments in this tree give wrong answers.
- **Host wait time overlaps GPU time.** Never add `cudaDeviceSynchronize` or drain time to kernel time. Real GPU idle = token time − GPU busy time, measured in the normal run (not with per-leaf syncs).
- **Nested stages:** never add a child stage to its parent. Wall-clock stage marks are sync-inflated; use them for shares only.
- **A rate above the measured 223 GB/s ceiling means the inputs are wrong**, not that the kernel is fast.

## Changes

- **New paths are opt-in** (env flag, default off) until `ak ledger check-promote` says
  `may_promote: true`. Promotion means: `implemented → gated → measured → confirmed`, the
  last one in a different session (after a reboot or on another day).
- **Pick the right gate.** Two classes of change, two gates:
  - *Refactors that must not change arithmetic* (load paths, fusion of identical ops,
    scheduling, I/O): bit-identical frontier logits plus identical greedy text. This stays
    the default; it is cheap and catches silent bugs (e.g. an FP16-WMMA scorer that passed
    at 32K and diverged at 64K). **Frontier logits are captured at the end of prefill, so
    they do not verify decode-only paths**; for those also require identical greedy text
    over >= 128 tokens and, where available, an in-kernel check mode against the old kernel.
  - *Changes that intentionally alter rounding or quantization* (reduction order,
    FMA contraction, requantized tensors, the decoder suffix): bit-exactness does not
    apply. Gate them like upstream (`QA_BEFORE_RELEASES.md` §3 and §17): the official
    V4.1 continuation scorer (`gguf-tools` quality-score with the
    `quality-testing/deepseek-v4.1-flash-2026091*` manifests, including `-general` for
    quantization) must stay in band versus the current default, plus long-prefix
    perplexity on prose/code/docs. Record the scores in the ledger. Larger-than-noise
    regressions are rejections, not trade-offs, unless the user accepts them.
- **Files compiled into other backends** (`cuda/`, `ds4_cuda.cu`, `metal/`): guard ROCm-only
  changes with `GGML_USE_HIP` / `DS4_ROCM_BUILD`.
- **Before writing code, record a hypothesis** with its mechanism and expected size
  (`ak ledger add --kind hypothesis`). If the measurement doesn't support it, mark it
  `rejected` with the reason. Retracting a claim marks the claims built on it `suspect`;
  re-check those before relying on them.
- **When a result contradicts the mechanism,** suspect the instrument's scope first, check it
  with `ak rate` / `ak budget`, and only then reason further.

## Benchmarks

- Launch only through `run_benchmark`, e.g. `{"payload":"bench-ak-NAME.sh","args":[]}`. It
  captures the Pi PID, session and pane and launches the supervisor detached.
- After launching, **issue no further tools**. The supervisor stops Pi and the backend, runs
  the payload and resumes this session.
- **Never** start shell launches, search for PIDs, overlap supervisors or model processes,
  or restart the backend yourself. If the launch fails, fix that concrete error.
- Supervisor settings are in `supervisor.d/<profile>.env` (see its README). Payloads are
  killed after `PAYLOAD_TIMEOUT`; set `est_run_s` in the A/B spec so `ak ab plan` checks the
  plan fits.
- After resume, read the run's `summary.json` and the `ak ab analyze` result
  (`verdicts`, `gate`, `warnings`, `order_effect_pct`, `clock_skew_pct`). Exit code 0 proves
  nothing.
- **A speedup is only real if `ak` says `win`.** Inconclusive or below the A/A noise floor
  means no effect. Run an A/A first for every new benchmark case (model, prompt, context,
  generation length, cache size).
- Keep model, prompt, cache size (the GB suffix matters), context, generation length and
  build fixed within an A/B. Current long-context work: 92GB cache / 128K context.
  Historical baseline: 76GB / 32K.

## Your response budget

DeepSeek's limit is **8,192 generated tokens per response**, shared by reasoning, text and
tool arguments. Free context does not raise it.
- **Plan briefly** and leave room for complete tool calls.
- **Large files:** write a small first part, extend it with separate edits, and run nothing until it is complete.
- **A rejected call was not executed.** Reissue it smaller; never continue truncated JSON.
- **Reading and editing:** prefer native read/grep/edit with scoped paths, `offset`/`limit` and short unique edit anchors. Batch disjoint edits to the same file.
- **Bash** is for builds, processes and parsing logs. Return aggregates, not dumps, and answer one question per output. A truncated result is incomplete: fetch only the missing range.
